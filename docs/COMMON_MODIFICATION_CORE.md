# Общий слой модификаций

Этот этап добавляет код общего контракта в `analysiscore`, без Android-зависимостей.
Новых APK, эмуляторных установок или релизов для этого этапа не требуется.
Коммиты `[code only]` запускают JVM-тесты `analysiscore` и выбранные тесты
DEX/native-нормализации в app. Предварительно проверяется dry-run графа задач:
assemble/package/install APK и native build запрещены. Генератор runtime-probe APK
исключён из графа, SDK устанавливается только для компиляции исходников. APK/Space
carrier, NDK bootstrap и device jobs пропускаются.
Флаг `-Pmodkit.codeOnly=true` отключает native-конфигурацию runtimeprobe/nativefixture
на время JVM-проверок, чтобы Gradle не пытался устанавливать NDK при настройке проекта. Полная Android-проверка и сборка
остаются отдельным этапом, когда будут готовы исполнители и интеграция.

## Контракт

`ModificationRequest` содержит точную идентичность источника (SHA-256), locator,
форму цели (метод/поле), представление кода (DEX/native/script), точку вмешательства,
тип и операцию. Название игры или движка не участвует в арифметике общего слоя.
Поддерживаются RESULT, ARGUMENT (с обязательным индексом), FIELD_READ и FIELD_WRITE.
Это описание точки, не доказательство существования её перехвата в конкретной игре.

`ScalarValue` различает Boolean, signed byte/short/int/long, unsigned char,
Float и Double. `ValueOperation` реализует replace/multiply/clamp. Long не
преобразуется в Double; переполнение и выход за узкую ширину запрещены. Float
вычисляется с Float-точностью. Нефинитные параметры не принимаются парсером;
исходный NaN остаётся NaN при умножении.

`ModificationDispatcher` применяет одну и ту же операцию к значению, которое
подал адаптер, во всех четырёх точках. Проверяются полная цель, точка и индекс
аргумента. OFF возвращает текущее исходное значение. Закрытая сессия не может
включиться снова. Несовместимый тип или целочисленное переполнение возвращают
исходное значение с диагностикой. Dispatcher сам не читает память и не ставит hook.

## Подготовка адаптером

`ModificationAdapter` отделяет подготовку кода от общего запроса.
`ModificationPlanner` проверяет capabilities, host (перепакованное приложение,
Space или root) и доказательства binding/type/original/preservation/restoration/local
scope. Пустой список блокеров означает, что проверены предпосылки; он не означает
подготовленный или установленный перехват.

`VerifiedRecipeAdapter` принимает только зарегистрированный точный запрос с уже
проверенным lowering. Изменение коэффициента, SHA или цели требует новых байтов
и повторной проверки. Дублирующийся ID не выбирает произвольный метод. Payload ID
ссылается на данные конкретного backend; исполнитель обязан установить их и
проверить runtime-идентичность. Root не создаёт backend и не даёт серверную authority.

## Связь с существующим кодом

`DexResultModificationAdapter` принимает копию исходного DEX, сканирует её
существующим проверенным сканером, сопоставляет общий RESULT/REPLACE с точным
поддержанным действием и создаёт реальные обратимые wrappers через
`DexRuntimeSwitchRewriter`. Оригинальный метод сохраняется в backup; перед rewrite
повторно проверяются источник и выбор методов. Другой коэффициент/метод/тип требует
нового lowering. Backend объявлен только для REPACKAGED_APP: это не новая поддержка
DEX внутри оригинального Space или root.

DEX/native каталоги записывают `AutoModRecipe.modificationRequests`. DEX mapping
сохраняет реальные return widths, включая byte/short/char/long/Float/Double.
Native mapping использует проверенный тип binding. `NativeResultModificationAdapter`
реально преобразует общий запрос RESULT/REPLACE или RESULT/MULTIPLY в проверенные
ARM64-байты существующими encoders. Native-каталог готовит множители через этот
адаптер: общий запрос уже участвует в генерации кода, а не только описывает его.
Адаптер снимает копию исходных байтов, отвергает другую цель/точку/ширину, проверяет
read-only proof и связывает payload с точным запросом и SHA новых байтов. При выборе нового scalar
параметра обновляются и байты, и общая операция; абсолютное значение не превращается
в множитель. Блокированные/нескалярные native-рецепты не получают фиктивный запрос.

Существующие native_v1 payload и DEX rewriting остаются исполнителями старого
протокола. Общий контракт ещё не подключён как новый wire-протокол Space. Перехват
аргументов и полей, произвольных native-функций с вызовами, Mono/script runtime,
а также новые root hooks этим этапом **не реализованы**. Это следующие адаптеры,
а не автоматически поддержанные возможности Minecraft/Aniimo/Star Dive.

## Проверки

Portable JVM-тесты проверяют арифметику во всех точках и представлениях, точные Long,
узкие границы, Boolean, Float/Double, NaN исходного результата, OFF/close,
разделение аргументов/целей, capabilities и точность зарегистрированного lowering.
App-тесты нормализации, native-каталога и DEX rewriting запускаются на JVM без
APK-упаковки. После этого независимый ARM64 Unicorn выполняет 36 векторов
реального выхода native-адаптера (12 простых и 24 с вычислениями/условиями).
Проверяются результат, неизменность памяти и исходный результат при возврате
оригинальных байтов. Это не исполнение внутри Space или сторонней игры. Android-интеграция и игровой эффект этого нового контракта пока
не проверены. Итоговый CI-результат записывается после завершения code-only задания.
