# ModKit Test 0.0.36 — совместимость локальных проверок установщика

После пересборки Android записывает ModKit как установщик нового APK. Это может
изменить результат локальной проверки магазина внутри приложения. Новый этап
сохраняет наблюдавшееся имя установщика исходного установленного пакета и адаптирует
точные DEX-вызовы, читающие это имя. Он не меняет системную запись установщика.

## Условия применения и границы

- Вход — установленное приложение, APK которого проверены по SHA. Пути base/splits
  повторно сопоставляются с текущей установленной версией до и после чтения метаданных.
- Имя установщика читается из PackageManager. Для файла APK, неизвестного источника
  или сменившегося установленного комплекта значение не выдумывается.
- Поддержаны `PackageManager.getInstallerPackageName`,
  `PackageManager.getInstallSourceInfo` и `InstallSourceInfo.getInstallingPackageName`.
  Перенаправляются только точные сигнатуры invoke-virtual / invoke-virtual-range.
- Bridge сначала выполняет настоящий Android-вызов. Ошибки и сведения о других
  пакетах сохраняются. Объекты InstallSourceInfo сопоставляются с выбранным пакетом
  через слабые ссылки; инициатор установки и прочие поля объекта не подменяются.
- Конфигурация загружается ContentProvider при старте процесса. Проверки до его
  создания, reflection/JNI, отдельные процессы, собственные загрузчики DEX и
  нативные проверки не покрыты.
- Подпись APK, лицензии, Play Integrity, покупки и серверная авторизация не
  объявляются исправленными этим этапом. Это не универсальный обход проверки магазина.

Встроенная запись связана с package name и SHA исходного APK-set. Уже пересобранный
APK с такой записью не обрабатывается как оригинал. Реальная подпись сборки остаётся
тестовой, системное подтверждение установки сохраняется.

## Проверка реализации

Новый `DexInstallerCompatibilityRewriter` сохраняет регистры, типы результата,
ширину инструкций, ветвления, try/catch и debug-данные. Тела изменённых методов
сверяются после повторного разбора. Новый bridge исключён из адаптации своих
собственных Android-вызовов. Этап проверяет содержимое всех ZIP-записей, источники
и неизменные splits; число перенаправленных вызовов записывается в отчёт сборки.

JVM-тесты покрывают обычные и range-вызовы с регистрами >255, обе ступени нового API,
сохранение ветвлений и обработчиков, неизвестные API, bridge, отмену, неверные
аргументы и привязку к исходному комплекту. Отдельно проверен DEX в code split.

Android-сценарий использует собственную игру: исходная установка от shell,
пересборка через обычный экран ModKit, установка от ModKit и чтение обоих API
внутри игры. Reflection независимо читает фактическую системную запись. Проверяются
перезапуск процесса, запрос другого пакета, исключение для отсутствующего пакета,
обычный APK и комплект splits. Вход из файла сохраняет исходное поведение API.

CI ещё выполняется. Готовность выпуска и результаты будут записаны после проверки.
Игровые рецепты и движки в этом выпуске не расширены.
