# Динамические множители native-геттеров

ModKit теперь может подготовить множитель результата вместо постоянного значения
для точных ARM64 Float/Double-геттеров в категориях урона, движения, скорости атаки
и регенерации. При каждом вызове сохраняется оригинальное чтение поля экземпляра,
а затем его результат умножается. Если поле изменяется в игре, результат мода
меняется вместе с ним. Это ограниченный result transform, не универсальный hook.

## Подготовка

`AArch64ResultTransformEncoder` требует начальное LDR S0/D0 из X0 с unsigned offset
и возможный BTI. После чтения допускаются доказанные вычисления и условия без
вызовов, записей и циклов. Все FP-инструкции должны сохранять точность Float/Double.
Исходные вычисления и адреса ветвлений сохраняются. Для каждого достижимого RET
нужны два следующих NOP, которые недостижимы в исходном графе; туда помещаются
FMOV, FMUL и новый RET. Короткий одиночный геттер также может использовать NOP
до возврата. Проверяется каждый путь, а не только первый RET.
Literal loads и ADR/ADRP отклоняются: недостижимые NOP могут использоваться как
PC-relative данные. Дополнительные инструкции занимают проверенные
NOP внутри известного диапазона до следующего метода. Нет перемещения исходной
инструкции, PC-relative relocation, вызовов, новых ветвлений или записи полей.
Коэффициент загружается в caller-saved V16; FMUL возвращает результат в S0/D0.

Нужны точный тип, единственный binding, полный проверенный function index,
уникальное тело, доказанная следующая граница и место до неё. Padding из нулей,
неподходящая инструкция после RET, вызов, store, несовместимая FP-ширина или отсутствие границы
не разрешают множитель. Когда множитель не подходит, существующая проверка
постоянного результата сохраняется; она не получает ослабленных условий.

Готовые коэффициенты: 0.5, 2, 3, 5, 10 и 16. Значение по умолчанию — 2.
В карточке показано «Множитель», заголовок содержит ×. Изменение коэффициента
обновляет конкретные байты. ID получает suffix `:multiply-v1`, поэтому ранее
сохранённый абсолютный параметр 5 не станет автоматически множителем ×5.
Методы отображения не получают такие автоматические рецепты.

## Выполнение в Space

Рецепт передаётся через существующий native_v1 payload как равные по длине
expected/replacement bytes. Текущий исполнитель проверяет ABI, loaded image SHA,
адрес и живые исходные байты. ON устанавливает преобразование; OFF и закрытие
сессии восстанавливают исходные байты, включая оригинальный RET и padding.
Работа мода не меняет сохранённое значение поля — она меняет чтение.

Это не field maintenance, не original-call trampoline и не поддержка геттеров
с побочными эффектами. Польза для игры требует проверки: смысл поля и authority
не выводятся из успешного CPU-теста. Root-анализ скрытых целей этим изменением
не реализован. Широкий каталог поиска остаётся отдельным слоем.

## Проверка

Добавлены проверки точного opcode, FP-ширины, BTI, допустимого padding, границы,
неверного владельца/регистра, calls/stores/loops и коэффициентов. Дополнительные проверки отвергают достижимый
padding, нехватку места на одном из возвратов и изменение FP-ширины. Каталог
проверяется вместе с созданием draft и изменением коэффициента.

12 CPU-векторов используют байты, реально выбранные каталогом: Float/Double,
четыре разных исходных значения (включая 0 и отрицательное), BTI, ×0.5 и ×5.
CI запускает их независимым ARM64 Unicorn-эмулятором и проверяет результат,
неизменность памяти и восстановленный исходный результат. Существующие Android
сценарии продолжают проверять установку и снятие native_v1 patches внутри гостя.
Они не заменяют проверку именно ARM64-множителя на физическом телефоне.

Проверки commit `67bb6e854e7d84a61b0c8c2aeeffcbc0d1804b36`:
[Android CI, run 38064538275](https://github.com/Ffenuss/ModKit/actions/runs/38064538275)
завершён успешно. Прошли модульные тесты, lint, сборка, все 12 новых ARM64-векторов
и существующие независимые native-векторы. Android 29: 9/9 instrumentation-тестов.
Android 35: 9/9 после одного повторного запуска только упавшего задания.

В первом прогоне Android 35 тестовая установка вернула `INSTALL_FAILED_ABORTED`
("User rejected permissions"), из-за чего упали сценарий установки и зависимый
сценарий сохранённой сборки. Архив исходного отчёта сохранён в CI. Повторный прогон
прошёл без изменения кода. Это не доказательство устранения всех возможных сбоев
системного установщика. Новые множители были успешно проверены отдельно до повтора.

Выбор caller-saved V16 сверён с
[официальным AAPCS64, SIMD and Floating-Point registers](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst).
Новый ARM64-множитель не проверен в сторонней игре или на физическом ARM64-телефоне.

## Расширение на вычисления и условия

Добавлены 24 независимых CPU-вектора из реально подготовленных рецептов каталога:
Float/Double, три исходных значения, обе ветви условия, общий возврат и два
отдельных возврата. Одна ветвь прибавляет 2, другая умножает исходное поле на 2;
мод умножает результат выбранной ветви, сохраняя исходную формулу. Проверяются
неизменность памяти и исходный результат после восстановления.

ID `:multiply-v1` сохранён: семантика параметра по-прежнему — множитель результата;
расширен только набор доказуемых тел. Условие может выбрать нулевой или отрицательный
результат — множитель сохраняет это поведение. Поддержка не охватывает произвольные
методы: начальное чтение поля, известная граница и свободные NOP остаются обязательными.
