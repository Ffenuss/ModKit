# ModKit Test 0.0.34 — переключаемые DEX-рецепты

## Причина и механизм

В 0.0.33 DEX-изменения применялись статически: выключение через оверлей было
невозможно. Новый путь сохраняет полное исходное тело каждого поддерживаемого
метода в закрытом synthetic-методе того же класса. На месте исходного метода
создаётся обёртка: при выключенном флаге вызывает сохранённый метод, при
включённом возвращает выбранную константу. Регистры, ветви и debug-информация
исходного тела не сдвигаются. У связанных чтений одного поля общий переключатель.

Обнаружение использует прежнюю проверку сигнатур, типов, полей и всех достижимых
ветвей; вызовы, записи, циклы и неподдерживаемые инструкции не разрешаются только
ради появления переключателя. Методы интерфейсов пока получают явный блокер.
Поддерживаются существующие локальные игровые рецепты Z/I/F без параметров.

После записи DEX проверяется каноническое представление исходного тела и
обёртки, включая регистры, ссылки и переходы. Отдельный этап APK-сборки связывает
свои входы с SHA предыдущего внедрения и проверяет содержимое всех ZIP-записей.
Неизменённые splits передаются дальше без дополнительной копии. Каталог разрешённых
DEX-переключателей помещается в base APK; неизвестные идентификаторы отвергаются.

Оверлей управляет DEX и нативными рецептами через один протокол. Чтение флага
в обёртке не захватывает блокировку. Включённые состояния не записываются на диск:
после перезапуска процесса всё выключено. Очистка и смена конфигурации выключают
старые флаги. Выключение восстанавливает логику, но не откатывает уже изменённые
игровые данные.

Повторные сборки сохраняются в отдельных каталогах попыток; незавершённая
попытка не удаляет предыдущий APK. После успешной сборки промежуточные копии
освобождаются. Исправлено поле ZIP-выравнивания `0xd935`: оно содержит требуемый
размер выравнивания, который учитывает apksig. Итоговый подписанный runtime APK
повторно проверяется на выравнивание библиотек до предложения установки.

## Проверки и границы

Добавлены проверки сохранения связанных геттеров, private/static вызовов,
ветвлений, Float, конфликтов имён, устаревших SHA, отмены и опасного тела с
побочным эффектом. Проверка APK-этапа охватывает DEX в split, неизменные ресурсы,
подмену файлов и существующий каталог. Android-сценарий использует собственную
тестовую игру и настоящий ART: здоровье, независимая выносливость, выключение,
перезапуск и смена конфигурации. UI-сценарий проверяет новый DEX-оверлей также
на комплекте APK.

Первый прогон обнаружил ошибку generic-типа в JVM-тесте и отказ установки
runtime APK на API 29 из-за выравнивания после подписи. Отдельные DEX/native
сценарии прошли на обеих API. Исправления прошли полный повторный прогон; Android-сценарий также подтвердил
сохранность ранее созданного APK.

Это не универсальное распознавание всех игр/приложений. Новые движки и Premium
сторонних программ не добавлены. Обёртки действуют в процессе с внедрённым probe;
отдельные процессы и собственные загрузчики классов требуют отдельной поддержки.
Обычные ограничения подписи Android сохраняются. Для получения переключателей
нужен исходный APK: ранее статически изменённое тело нельзя восстановить без него.

Новый backend: `DexRuntimeSwitchRewriter`, `RepackedRuntimeDexSwitchInjector`,
`RuntimeDexSwitches`. Он запускается только при сборке выбранных DEX-рецептов;
нативный этап используется совместно, а прежний статический путь остаётся для
существующих экспертных сценариев и независимой регрессионной проверки.
