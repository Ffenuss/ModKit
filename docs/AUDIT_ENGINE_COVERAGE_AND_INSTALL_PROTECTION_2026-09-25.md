Date: 2026-09-25. Baseline: PR #10 at `03589a5949cdd9e7ed1724ea38cc4d42e30b0ca5`, stacked onto #9 → #8 → #7 (0.0.30). **This document is an audit, not an implementation of protection removal or additional game mods.** `main` is unchanged.

Evidence: user-supplied screenshots of Aniimo, Delta Force, Minecraft, STAR DIVE, TWoM and DropTheCat, and inspection of the above repository tree. APKs, per-app diagnostic ZIPs and matching logcats for these six tests have **not** been provided. ### The three observed result groups are *symptoms*, not engine taxonomy

1. **Zero**: can mean unrecognized/unsupported engine; IL2CPP with missing validated metadata (Aniimo); DEX with no semantically or structurally supported method; partial APK/split; scanning failures hidden as warnings. These need distinct statuses.
2. **Exactly one**: can be a framework false positive (`SemaphoreSegment`) or a genuine *display-only* method (`UI_ProgressBox`). A syntactically patchable method is **not** automatically a useful game modification.
3. **Many found, few enabled**: usually evidence gating, not just UI filtering. Keep blocked candidates with grouped, precise reasons; enrich only promising targets with targeted proof and preserve hard safety gates.

### Installer provenance / integrity: separate mechanisms and expectations

- **Android package signing**: all rebuilt APKs must remain validly signed. A changed signature will not replace an installed same-package original signed with a different certificate. Never auto-uninstall originals or silently delete their data.
- **Installed package origin**: API 30+ `PackageManager.getInstallSourceInfo`; API 29 `getInstallerPackageName` is a fallback for supported scenarios. An APK file does **not** contain a trustworthy record of which installer will install its future rebuilt copy. Package-source fields are signals, not proof of runtime app enforcement. Official reference: https://developer.android.com/reference/android/content/pm/PackageManager.
- **Local app checks**: an authorized app can implement installer-package checks or compare signing certificates at runtime. Static bytecode/symbol/dependency references can suggest these checks, but code paths and launch-time behavior must be verified.
- **Google Play automatic protection**: Play may inject runtime installer/anti-tamper enforcement into distributed versions; failing checks may display a prompt to get the app on Google Play. A different installer/signature and the overlay itself can also raise integrity/risk signals. See https://developer.android.com/games/playgames/integrity.
- **Play Integrity/backend**: a backend can validate signed verdicts and reject modified APKs independent of client-only changes. See https://developer.android.com/google/play/integrity/overview.
- **Explicit scope**: diagnose each mechanism and support test variants for **owned or expressly authorized** apps using the developer's source, test signing key/whitelisted backend or permitted local build changes. Do **not** promise blanket automatic removal from arbitrary third-party games, spoof valid certificates, alter platform package verification, or present an offline diagnostic as proof of bypass.
