# ModKit

Android-приложение для анализа и локальных изменений собственных или разрешённых APK.
Рабочая версия этой ветки: **0.0.35**. Проект не является универсальным автоматическим
моддером: подтверждённые возможности и оставшиеся ограничения перечислены ниже.

## Использование на телефоне

1. Выберите установленную игру, приложение или отдельный APK.
2. Нажмите «Анализ». ModKit определит технологии и проверит доступные рецепты.
3. Отметьте изменения по категориям и нажмите «Создать мод».
4. Дождитесь проверки патчей, подписи и сохранения. Нажмите «Установить».
5. Подтвердите установку в Android, нажмите «Запустить с мод-меню» и включите
   нужное изменение через кнопку MK. При первом запуске все изменения выключены.

Основной сценарий не требует root, компьютера, HEX-редактора или облачного сервиса.
В меню «Ещё» находятся экспертный режим и экспорт диагностики с причинами блокировок.

Тестовая сборка называется **ModKit Test** и использует пакет
`io.github.ffenuss.modkit.test`. Она устанавливается рядом с прежним ModKit и
не требует его удаления. История и ключи двух приложений хранятся раздельно.

Один исходный APK даёт один APK. Для установленного приложения со split APK
ModKit сохраняет отдельные APK и передаёт весь набор одной сессией PackageInstaller.
На Android 10+ результат сохраняется в **Загрузки/ModKit**. На Android 8/9
кнопка сохранения предлагает системный выбор папки. Новая попытка не удаляет
предыдущую подписанную сборку.

Если оригинал подписан другим ключом, Android не разрешит обновить его полученным
APK. ModKit не удаляет оригинал. Самостоятельное удаление приложения может стереть
его локальные сохранения — сохраните данные заранее.

## Что поддерживает эта версия

| Область | Поддержка | Граница подтверждения |
|---|---|---|
| DEX | Анализ всех методов поддерживаемых DEX без остановки на 256 кандидатах; константы, чтения полей Z/I/F и вычисления с ветвлениями; переписывание через dexlib2 и повторный разбор | Проверяются все достижимые пути и входные регистры; вызовы, записи, циклы и неизвестные инструкции остаются блокерами |
| Частичная обфускация | Восстановление геттера по фактически читаемому полю; согласованная группа чтений одного поля | Полностью переименованные поля и сложный поток данных пока не восстанавливаются автоматически |
| Unity IL2CPP / ARM64 | Metadata/ELF bindings, файловый индекс адресов, проверка ветвей, выбор конкретного скалярного значения, компактный FMOV, сохранение BTI | Поддерживаемые layouts/инструкции; неизвестные ABI, побочные эффекты и общие тела требуют дополнительного анализа; реальный Unity runtime ещё не испытан |
| Оверлей DEX и native | Включение выбранных DEX-рецептов с сохранением исходных тел методов; восстановление нативных байтов; согласование переключателей с процессом приложения | Собственная DEX-игра и JNI-функция на Android 10/15 x86_64; автоматическое обнаружение IL2CPP и физический ARM64 этим не подтверждаются |
| Сборка | Одна транзакция для выбранных DEX и native изменений; проверка конфликтов, SHA, diff, выравнивания, подписи и состава APK-set | Успешная сборка не означает работающий игровой эффект |
| Установка | Системное подтверждение, разрешение неизвестного источника, проверка сертификата, один сеанс для split APK, контроль переданных байтов | Поведение OEM и все версии Android требуют отдельной проверки |
| Проверка эффекта | Собственная офлайн-игра и Android UI/функциональные испытания; сценарий ручной проверки и сохранение наблюдения | Наблюдение пользователя не считается автоматическим доказательством |

Список поддерживаемых игровых категорий расширяем. Отсутствие готового рецепта
показывается явно. Серверная авторизация, покупка контента и защищённые серверные
значения не объявляются офлайн-патчами. Root-интерфейс прежних веток в текущем
приложении отсутствует.

## Изменения 0.0.35 для проверки на телефоне

- При обычном запуске «с мод-меню» остаётся одна внешняя кнопка MK. Встроенная
  кнопка не дублирует её. Экспертный запуск по умолчанию использует встроенное меню.
- Выбор меню сохраняется после перезапуска приложения. Закрытие внешнего окна
  не включает встроенную кнопку; управление можно снова открыть из ModKit.
- Для установленного мода со старым внедрённым кодом показывается требование
  пересоздать мод. Старый код не объявляется поддерживающим новый режим.
- На Android 10 и 15 проверены оба режима, перезапуск, переход обратно во внешнее
  меню и фактическая работа переключателя после смены режима.

Заново создайте мод из **исходного APK**, установите его и запустите через ModKit.
Все DEX/native возможности 0.0.34 сохранены; новых игровых рецептов в 0.0.35 нет.

[Проверки и ограничения 0.0.35](docs/RELEASE_0.0.35.md).

## Изменения 0.0.34

- Выбранные DEX-рецепты включаются и выключаются через оверлей. Исходные тела
  методов сохраняются; выключение возвращает исходную логику. Связанные геттеры
  одного поля управляются одним переключателем.
- После перезапуска процесса, очистки или замены конфигурации DEX-моды выключены.
  Выключение не откатывает уже изменённые игровые данные.
- Повторная сборка не перезаписывает предыдущий APK. Промежуточные файлы удаляются
  после успеха; ошибка новой попытки не затрагивает прежнюю сборку.
- Исправлено сохранение выравнивания нативных библиотек при подписи; проверяется
  уже подписанный APK, который будет передан установщику.

Для нового оверлея заново создайте мод из **исходного APK**, установите его
и запустите через ModKit. Статически изменённая игра из старой версии не содержит
сохранённых исходных методов.

[Проверки и ограничения 0.0.34](docs/RELEASE_0.0.34.md).

## Изменения 0.0.33

- Исправлена невидимая панель внешнего оверлея. Переключатели становятся доступны
  после ответа приложения, а после команды показывают подтверждённое состояние.
- Повторное открытие меню читает активные изменения из процесса. После перезапуска
  приложения состояния обновляются; прежние изменения не включаются автоматически.
- Замена или очистка конфигурации восстанавливает исходный код. Выполнение
  нативной команды и изменение конфигурации защищены общей блокировкой.
- Включены исправления 0.0.32: положительное значение для коротких Float/Double
  геттеров вместо случайного нуля и восстановление журнала анализа после прерывания.

После обновления ModKit заново создайте и установите мод приложения: новый
протокол находится во внедряемом коде, а не только в самом ModKit.

[Проверки и ограничения 0.0.33](docs/RELEASE_0.0.33.md),
[изменения 0.0.32](docs/RELEASE_0.0.32.md).

## Изменения 0.0.31

- Общая сборка веток #8–#17, включая отдельное исправление #12:
  ложный `kotlinx.coroutines.sync.SemaphoreSegment.getMaxSlots` больше не предлагается как инвентарь игры.
- IL2CPP: все поддерживаемые MethodDef обрабатываются до конца; 30 000 ограничивает
  только предпросмотр в памяти. SHA-проверенный файловый индекс, поиск поздних
  методов и полный `bindings.tsv` работают за этой границей. Отдельный предел
  чтения метаданных 300 000 остаётся; неполные метаданные отмечаются явно.
- Unreal: фактическая проверка PAK footer / SHA-1 индекса, UASSET и IoStore-заголовков.
  Flutter: разбор `AssetManifest.bin` и учёт нативных компонентов. Это анализ
  ресурсов; Blueprint/Dart AOT и генерация игровых патчей пока не поддерживаются.
- ELF: прогресс по копируемым байтам и имени библиотеки, очистка прерванной
  выгрузки, отдельный порог watchdog для больших ELF.
- Отчёт схемы 3 включает маршрутизацию, признаки движков, SHA исходных APK/splits,
  предупреждения и охват анализа. Повторный экспорт отражает текущие результаты.
- В интерфейсе отдельно показаны прочитанные методы, точные привязки и
  предпросмотр. Эти числа не являются числом работающих модификаций.

## Сборка для разработчиков

Java 17, Gradle 9.5.0, Android SDK 37.0, Build Tools 36.0.0, NDK 28.2.13676358:

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

GitHub Actions также запускает `:app:connectedDebugAndroidTest` на Android 10 и 15.
Самостоятельная игра `testgame` содержит механики здоровья и выносливости, связанный
обфусцированный геттер и метод-ловушку с побочным эффектом. Скрипт
`tools/install_device_fixture.sh` устанавливает исключительно эту тестовую игру.
Обычному пользователю эти инструменты не требуются.

CI дополнительно исполняет сформированные Kotlin-кодом ARM64-патчи в Unicorn 2.1.4.
Это независимая проверка машинных инструкций; Unicorn не включён в приложение.

Модуль `nativefixture` отдельно проверяет production-внедрение probe, системную
установку и фактическое выполнение JNI-функции через внешний оверлей: 7 → 999 → 7.
Также проверяются повторное открытие меню, перезапуск процесса, отказ для
отсутствующего модуля и восстановление кода при замене/очистке конфигурации.

CI debug APK подписывается ключом runner; такой ключ не подходит для постоянных
обновлений. Выдаваемый тестовый APK дополнительно подписывается сохранённым закрытым
тестовым ключом через `tools/SignTestApk.java` (apksig 9.3.0). Ключ не входит в Git.
Установочные сборки из разных каналов могут иметь разные сертификаты.

Действуют [правила разработки](CONTRIBUTING.md) и исходная спецификация проекта.

### DEX wide-геттеры (0.0.39)

- Локальные Java/Kotlin-геттеры `long` и `double` распознаются для доказанных
  констант и чтений поля своего класса. Перезапись использует пару регистров,
  `const-wide` и `return-wide`; битовое представление `double` сохраняется точно.
- Runtime-меню сохраняет исходное тело и вызывает его при OFF. Для `this` выделен
  отдельный регистр; статические методы используют отдельный путь вызова.
- Owned ART-тест проверяет `4294967298L → 9999L → 4294967298L` и
  `1.25 → 2.0 → 1.25`, независимость двух переключателей и сброс при рестарте.
- В 0.0.39 вычисляемые wide-тела, параметры DEX-геттеров и методы с побочными
  эффектами оставались неподдерживаемыми. Это расширяет типы рецептов, но не означает
  универсальную поддержку движков и версий.

### Вычисляемые DEX wide-геттеры (0.0.40)

- Анализ ациклического потока данных теперь проверяет пары регистров на каждой
  ветви: wide-константы, чтения своих полей, перемещения, сравнения, преобразования,
  арифметику `long`/`double` и long-сдвиги с узким счётчиком. Запись одной половины
  аннулирует прежнюю пару; на слиянии сохраняются только общие факты всех путей.
- Owned ART-геттеры с условиями и вычислениями проходят прежний runtime-сценарий
  переключения, независимости, восстановления и рестарта. Простые геттеры
  продолжают использовать свой доказанный путь.
- Вызовы, записи состояния, циклы, обработчики исключений, несовпадающая ширина
  поля/результата и целочисленные DIV/REM остаются заблокированными.

### Примитивные аргументы DEX-геттеров (0.0.41)

- Поддерживаются до восьми примитивных аргументов; пары `long`/`double`
  и положение `this` учитываются в анализе входного регистра каждого метода.
- При OFF исходный метод получает исходные аргументы. Большие наборы слов
  передаются через `invoke-*/range`; перегрузки проверяются по полной сигнатуре.
- Параметры отражены в существующих названиях рецептов; прямые чтения одного
  поля с разными параметрами не объединяются молча в один переключатель.
- Owned ART-сценарий проверяет instance `getAmmo(long)` и static
  `getRunSpeed(long, double, long)`: последний требует шести входных слов.
  Исходные значения, независимость, восстановление и сброс при рестарте
  проверяются через прежнее мод-меню. Объекты и массивы остаются исключёнными.

### DEX-геттеры с switch (0.0.42)

- Анализ поддерживает `packed-switch` и `sparse-switch` в ациклических
  скалярных телах. Проверяются все case-ветви и путь без совпадения, полные
  пары регистров на слиянии и отсутствие вызовов/записей/циклов.
- Таблица должна иметь правильный тип, выравнивание, упорядоченные ключи
  и не более 256 элементов. Переходы вычисляются относительно switch;
  переход в таблицу, середину инструкции или за границы тела запрещён.
- Owned ART-сценарий переключает все три case-значения и default для
  instance `getAmmo(long, int)` и static `getRunSpeed(long, double, long, int)`.
  Проверяются исходные результаты, замена при ON и полное восстановление
  всех ветвей при OFF через прежние четыре кнопки мод-меню.
